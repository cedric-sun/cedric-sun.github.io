Android 開放原始碼專案的工作副本及其建置成品需要大量磁碟空間；確切需求取決於分支、目標與啟用的變體。請使用具備充足 RAM、快速儲存裝置，以及足夠可用空間來容納工作副本與輸出目錄的 64 位元 Linux 主機。

取得原始碼 #

AOSP 分散在許多 Git 儲存庫中。repo 工具會根據資訊清單協調這些儲存庫；它是 Git 的 Python 包裝器，而不是獨立的原始碼控制系統。使用 repo init 初始化所需分支，再使用 repo sync 填入或更新工作副本。

Android 的建置系統是 Soong。模組定義通常是 Android.bp Blueprint 檔案；Soong 使用 Ninja 執行建置，而 Kati 支援其餘的 Android Make 相容層。在呼叫該分支所記錄的建置目標之前，請使用 AOSP 環境設定腳本選取產品與建置變體。

執行映像檔 #

僅使用目標支援的映像檔與機器設定來執行模擬器或 QEMU。Android 產品具有硬體特定性：開機韌體、核心、分割區與裝置設定必須彼此相符。對於一般 x86_64 開發，Android Emulator 通常是受支援的選擇；若要試驗相容的核心、韌體與磁碟配置，QEMU 很有用。
