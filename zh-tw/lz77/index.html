LZ77 滑動視窗壓縮

LZ77 是一系列無失真壓縮器，會將重複的輸入替換為指向有限歷史視窗的參照。原始的 1977 年設計使用滑動字典；實務格式會自行選擇 token 語法、比對尋找器與熵編碼器。

文字、歷史與比對 #

在輸入位置上，編碼器會在先前輸出的位元組中尋找相符的前綴。不存在有用的比對時會輸出文字，否則會輸出至少包含距離與長度的回溯參照。有些格式會在每次比對後加入文字；另一些則輸出由獨立文字與比對組成的串流。解碼器會從目前輸出位置之前 distance 個位元組處複製 length 個位元組。

複製來源可能重疊。如果歷史以 a 結尾，距離為 1、長度為 5 的比對會產生 aaaaa：每個複製的位元組都會成為下一個位元組的來源。解碼器必須依正向位元組順序複製，或使用具備等效連鎖語意的迴圈。memcpy 與快照式的 memmove 都無法實作每一種有效的重疊比對。

比對搜尋與剖析 #

較大的視窗能找到更遠的重複內容，但會消耗更多記憶體，且需要更多距離位元。雜湊鏈、二元樹、後綴結構與有界候選搜尋，會在壓縮率與 CPU 時間之間取捨。

貪婪剖析器會選擇目前位置的最長比對。延遲剖析器會先記錄候選比對，檢查下一個位置是否有更好的比對，並在這能改善總成本時改為輸出文字。動態規劃可以搜尋更大的剖析空間，但需要更多 CPU 與記憶體。這些編碼器選擇都不會影響解碼器正確性，因為 token 串流是自包含的。

界限與防禦式解碼 #

每種格式都會定義自己的最小比對長度、最大長度、視窗大小與距離編碼。例如，DEFLATE 允許最遠 32 KiB 的距離，以及最長 258 位元組的長度。解碼器必須拒絕大於目前可用歷史的距離、無效的長度或距離碼、計算輸出位置時的整數溢位，以及超出呼叫者限制的輸出。資源限制應同時涵蓋總輸出量與工作量，因為小型輸入可能展開成非常大的輸出串流。

DEFLATE 與相關格式 #

DEFLATE 使用 Huffman 樹對文字／長度與距離符號進行熵編碼，接著使用 LZ77 視窗取得參照的位元組。LZ4 在相同的複製操作周圍使用精簡 token 格式，而 Zstandard 將視窗式 LZ 比對階段與不同的熵編碼器結合。LZ78 與 LZW 則維護片語的明確字典；它們的字典更新規則不能取代 LZ77 歷史參照。

參考資料 #
