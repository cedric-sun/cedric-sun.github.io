Linux 网络功能通过主线版本的渐进式发布演进，而不是通过独立的子系统版本发布。以下里程碑标识了首次包含各项功能的稳定内核版本；后续内核可能会增加协议覆盖范围、驱动程序、卸载功能或用户空间接口。

内核与用户空间边界 #

Linux 不提供add_route()或create_veth()之类的系统调用。相反，用户空间选择内核控制接口，并通过通用系统调用访问它。尤其需要注意，Netlink 是一组套接字协议，而不是一个系统调用。

SyscallsControl InterfaceNetwork Configuration RoleCurrent Guidance

大多数管理操作要求在管理目标网络命名空间的用户命名空间中拥有CAP_NET_ADMIN。根据程序类型、附加点和内核版本，eBPF 操作还可能需要CAP_BPF、CAP_PERFMON或其他能力。

推荐接口的变化 #

  1. 早期 Linux 使用 ioctl、套接字选项和虚拟文件。 ifconfig、route和arp等程序发出网络设备和路由 ioctl。/proc/sys/net提供全局调节项，而通过旧版 iptables 配置的各代防火墙使用协议特定的套接字选项。
  2. Rtnetlink 成为可扩展的网络控制平面。 Linux 2.2 通过NETLINK_ROUTE公开链路、多个地址、路由、邻居和流量控制对象。因此，iproute2 工具（ip、bridge和tc）取代了面向 ioctl 的 net-tools 命令，用于新的配置。
  3. 特定于子系统的 Netlink 家族取代了固定的私有 ABI。 Generic Netlink 及相关协议允许命令和类型-长度-值属性在不更改系统调用的情况下演进。nl80211 取代 Wireless Extensions，nftables 取代旧版 iptables 规则 ABI，而较新的 ethtool 操作使用 Netlink 而不是设备 ioctl。
  4. eBPF 增加了可编程的数据平面边界。 bpf()系统调用管理程序和映射，但配置仍按附加点划分：rtnetlink 配置流量控制和既有的 XDP 附加，套接字选项附加经典套接字过滤器，而 BPF 链接为受支持的钩子提供文件描述符生命周期管理。
  5. 新的控制平面倾向于使用有描述的 Netlink API。 当前的内核网络开发通过机器可读规范记录 Netlink 家族。应用程序应使用这些 API，请求确认和扩展确认，并仅在不存在受支持的结构化替代接口时使用 ioctl 或文本文件解析。

有关相应 UAPI 的详细信息，请参阅内核的Netlink 介绍、rtnetlink(7)、netdevice(7)和bpf(2)文档。

Rtnetlink #

rtnetlink 中的rt表示routing，但该接口已经发展为内核的通用网络控制协议。进程打开socket(AF_NETLINK, SOCK_RAW, NETLINK_ROUTE)并发送RTM_*消息。每条消息包含struct nlmsghdr、对象特定的固定头部以及对齐的类型-长度-值属性。

Rtnetlink 支持三种交互模式：

  • Do request: 创建、替换、修改或删除一个对象，并接收确认。
  • Dump request: 枚举一类对象，例如所有链路或所有路由。内核返回以NLMSG_DONE结束的分段响应。
  • Multicast notification: 订阅链路、地址、路由、邻居、规则、流量控制及其他变更的组。通知使用与回复相同的对象消息，因此程序可以维护本地缓存。

命名空间与一致性模型 #

rtnetlink 套接字在其所属的网络命名空间中运行。因此，大多数请求只能查看和修改该命名空间中的链路、路由、规则、邻居和流量控制对象。链路属性可以将设备移动到另一个命名空间，而命名空间 ID 消息则可以创建对等命名空间的引用。

修改请求通常要求在拥有目标网络命名空间的用户命名空间中具有CAP_NET_ADMIN。当读取请求暴露敏感的设备或协议信息时，也可能受到限制。

转储不是原子快照。在分段转储进行期间，对象可能发生变化；当接收缓冲区溢出时，多播通知可能丢失。状态同步器应：

  1. 打开套接字并将其绑定到所需的多播组。
  2. 使用唯一的序列号请求转储。
  3. 根据序列号和发送方端口 ID 匹配单播回复。
  4. 处理转储期间到达的通知。
  5. 检测ENOBUFS、被中断的转储和格式错误的属性。
  6. 当无法证明同步完成时，丢弃缓存并重新执行转储。

用户空间网络工具 #

Linux 没有单一的用户空间网络栈。命令行工具、策略守护进程、配置渲染器、路由守护进程和容器插件会访问不同的内核控制接口。因此，高级命令可能控制的是守护进程，而不是直接联系内核。

SoftwarePrimary RolePath to the Kernel
iproute2ip管理链路、地址、路由、规则、邻居和网络命名空间；bridge管理网桥状态；tc管理流量控制；ss检查套接字。这些程序直接使用 iproute2 的内部 Netlink 支持。大多数配置通过 rtnetlink 完成；套接字检查使用诊断 Netlink 家族。iproute2 是一组可执行文件，而不是其他网络管理器所需的守护进程。
NetworkManager维护以太网、Wi-Fi、移动宽带、VPN、IP 配置和 DNS 集成的连接配置文件与策略。nmcli、nmtui、桌面小程序和应用程序都是客户端。nmcli使用 libnm，通过 D-Bus 调用 NetworkManager 守护进程。守护进程的 Linux 平台层会直接打开 Netlink 套接字，执行常规链路、地址、路由、规则和流量控制操作；它不会通过ip可执行文件发送这些操作。可选的辅助程序处理 Wi-Fi 身份验证、PPP、DHCP、DNS 和防火墙集成等功能。
systemd-networkd应用声明式的.network、.netdev和.link配置，运行 DHCP 和路由器发现客户端，并维护网络状态。networkctl是其检查和控制 CLI。systemd-networkd使用 systemd 内部的 Netlink 实现配置内核。对于受管理配置，networkctl使用 networkd API 和状态，而不是调用 iproute2。
Netplan将发行版级别的 YAML 转换为后端配置，并协调该配置的应用。Netplan 选择 NetworkManager 或 systemd-networkd 作为渲染器。持续执行内核配置的是选定的守护进程，而不是 Netplan 的 YAML 解析器。
nftablesnft创建防火墙、NAT、数据包分类以及集合或映射规则。libnftables 向应用程序公开相同的引擎。nft使用 libnftables 和 libnftnl，通过NETLINK_NETFILTER与 nftables 子系统交换批量消息；它不使用 rtnetlink 或 iproute2。
firewalld维护动态防火墙区域、服务、策略以及独立的运行时和持久配置。firewall-cmd是其主要 CLI。firewall-cmd通过 D-Bus 调用 firewalld 守护进程。该守护进程通常通过 nftables 后端应用规则，而不是要求 NetworkManager 或 iproute2 安装规则。
ethtool读取和更改驱动程序与 NIC 属性，例如链路模式、通道、环、合并、卸载、RSS、统计信息和固件数据。较新的操作使用 ethtool Generic Netlink 家族。较旧或尚未转换的操作使用SIOCETHTOOL ioctl，因此实际路径取决于命令和内核支持。
iw检查和配置 802.11 物理设备、虚拟接口、信道、站点、扫描、省电和监管状态。iw向nl80211 Generic Netlink 家族发送命令。它不会调用ip，但生成接口的普通链路和 IP 层配置仍由ip负责。
wpa_supplicant and iwd执行 Wi-Fi 扫描、身份验证、关联、漫游和密钥管理。每个守护进程都通过nl80211控制 cfg80211/mac80211。NetworkManager 可以通过 D-Bus 控制任一守护进程；随后由 Wi-Fi 守护进程与内核通信。
conntrack-tools列出、修改、监视和复制 Netfilter 连接跟踪状态。conntrack和conntrackd通过NETLINK_NETFILTER上的 ctnetlink 工作，独立于 rtnetlink。
bpftool加载和检查 eBPF 程序、映射、链接、BTF、cgroup 以及选定的网络附加关系。大多数对象生命周期操作使用 libbpf 和bpf()系统调用。部分网络操作还会检查或修改由 rtnetlink 管理的 XDP 和流量控制状态。
FRRouting and BIRD实现 BGP、OSPF、IS-IS 和 RIP 等路由协议，并将学习到的路由与内核 FIB 进行协调。FRRouting 协议守护进程将路由提交给其zebra守护进程，由后者通过 rtnetlink 配置内核。BIRD 在 Linux 上通过路由套接字或 Netlink 执行自己的内核协议同步。两者在稳定状态下安装路由都不需要ip可执行文件。
Open vSwitch为虚拟化、容器、覆盖网络和软件定义网络实现可编程虚拟交换。ovs-vsctl修改 OVS 数据库；ovs-vswitchd使用该配置，并通过 OVS Generic Netlink 家族控制 Linux OVS 数据路径。辅助链路和隧道设置也可能涉及 rtnetlink。
CNI plugins当兼容的运行时调用插件时，配置容器网络命名空间。常见插件会创建 veth 对、网桥、路由、策略和覆盖网络。插件以短生命周期程序运行，并通常直接使用 Go Netlink 库。插件还可能调用或链接防火墙、eBPF、IPAM 或数据存储组件；CNI 规定的是调用和结果格式，而不是单一的内核后端。
net-tools提供旧版ifconfig、route、arp和netstat命令。这些工具主要使用网络设备和路由 ioctl，并解析 procfs。对于新的自动化，iproute2 和结构化 Netlink 接口已经取代它们。

该图直接回答了常见的nmcli依赖问题：

  1. nmcli通过libnm构造请求。
  2. libnm通过D-Bus将请求发送给NetworkManager 守护进程。
  3. NetworkManager 通过自己的 Netlink 实现应用普通的内核网络状态。
  4. iproute2 是同一内核 API 的独立管理客户端，而不是 NetworkManager 与内核之间的中间层。

在 shell 自动化中，从程序调用ip、nft或其他 CLI 仍然有用，但长期运行的管理器通常使用库，或直接实现内核协议。直接访问可以避免解析命令输出，并允许管理器订阅异步状态通知。
