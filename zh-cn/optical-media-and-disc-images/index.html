光学介质与光盘映像

光学介质、扇区格式、文件系统和映像文件属于不同层次。可挂载的 .iso 可以复现数据卷，但可能省略音轨、会话边界、子通道和刻录属性。因此，映像格式必须根据目标任务选择：文件分发、启动、仿真或保存。

轨道、标记与读取 #

CD、DVD 和 Blu-ray Disc (BD) 沿螺旋轨道存储其程序区。聚焦后的激光从内侧程序区向外侧跟踪这条螺旋线，光学拾取器根据反射光的变化生成信号。由于圆周向盘片边缘逐渐增大，旋转通常采用恒定线速度或分区策略。

压制的只读光盘会在聚碳酸酯中模制出浮雕图案，并添加反射层。“凹坑”和“平地”描述的是物理层级，而不是字面意义上的 0 和 1 单元。跳变和游程长度产生通道信号，然后由驱动器进行解码和纠错。CD 使用 Eight-to-Fourteen Modulation 和 Cross-Interleaved Reed–Solomon Code；只有在这些底层完成解码后，才会出现扇区级字节。

不同产品系列的物理尺寸不同。标准 CD 是厚度为 1.2 mm 的聚碳酸酯光盘，使用近红外激光读取，轨道间距为 1.6 µm。DVD 通过波长更短的红色激光、更小的标记和间距，以及可选的第二层来提高密度。BD 使用蓝紫色激光，轨道间距约为 0.32 µm。共享螺旋轨道这一概念，并不意味着它们的光学系统、通道编码或扇区格式可以互换。

压制、可记录与可重写介质 #

制造方式和记录方式决定标记如何形成：

  1. 压制的只读介质将母版上的浮雕复制到模制基片中。电铸将显影后的玻璃母盘制成金属压模；经过模制、金属化、粘合、涂漆和贴标后，制成成品光盘。
  2. 可记录介质只能写入一次。CD-R 和传统的可记录 DVD 格式会改变有机染料，而常见的 BD-R 设计使用无机记录层。写入后的对比度模拟兼容驱动器预期的读取行为。
  3. 可重写介质使用可逆记录层，通常是相变合金。加热会使区域在反射率不同的状态之间切换。

可记录光盘包含预先形成的导槽，用于引导刻录机，并携带特定于格式的寻址或时序信息。可重写并不意味着具有类似磁盘的原子更新能力：分组写入软件、缺陷管理、文件系统规则和介质封盘仍会限制变更。仅凭材料颜色无法识别具体配方，也无法预测归档寿命。

轨道与会话 #

CD 轨道是一个连续流，并声明了类型，例如 CD Digital Audio (CD-DA) 或 CD-ROM 数据模式。一张光盘可以包含多个轨道。混合模式和 CD Extra 布局按照特定顺序规则组合音频与数据；轨道控制标志告诉播放器应如何解释它们。

一个会话将一次刻录操作中写入的一个或多个轨道分组，并添加导入区和导出区结构。多会话读取器使用会话元数据定位轨道并选择文件系统视图。追加会话可以公开一棵引用早期会话数据的新目录树，但不会重写已经记录的扇区。只复制文件会丢失这些关系。

规范系列与扇区 #

以颜色命名的 Rainbow Books 定义了 CD 系列格式：

  • Red Book 规定 CD-DA。
  • Yellow Book 规定 CD-ROM 模式。
  • Orange Book 涵盖可记录 CD 和可重写 CD。
  • Green Book、White Book 和 Blue Book 分别定义 CD-i、Video CD 和 Enhanced CD 应用。

ECMA-130 和 ISO/IEC 10149 标准化 CD-ROM 的记录方式和扇区组织，而 IEC 60908 涵盖 CD-DA。ISO 9660 在 CD-ROM 扇区之上定义独立的卷结构和文件结构。DVD Forum 规范和 Blu-ray Disc Association 的规范书分别定义各自的介质；DVD 和 BD 并不是 Rainbow Book 格式。

传统的已解码 CD 扇区包含 2,352 字节。CD-DA 将全部 2,352 字节用于音频采样。CD-ROM Mode 1 扇区提供 2,048 字节的用户数据，其余字节用于同步、寻址、错误检测和附加纠错。Mode 2 的形式会以不同方式划分这些字节。因此，“扇区大小”必须说明指的是通道数据、原始已解码扇区，还是文件系统可见的用户数据。

文件系统层与启动层 #

光学文件系统使用用户数据扇区，但它们不定义光学标记或全部轨道元数据。

ISO 9660 与扩展 #

ISO 9660 源自 High Sierra 格式，定义了可移植的只读卷和目录结构。其基本交换级别限制名称和目录组织方式。Rock Ridge 在 System Use 字段中记录面向 POSIX 的名称、链接、权限和设备信息。Joliet 增加了由 Microsoft 定义的 Unicode 目录树。读取器必须明确支持所选扩展。

UDF #

Optical Storage Technology Association 的 Universal Disk Format (UDF) 专门化了 ECMA-167 定义的卷结构和文件结构。UDF 支持 DVD、BD、分组写入和一次性写入所需的介质模型与更新模型。修订版本和介质配置文件的兼容性很重要，因为读取器支持 UDF 并不代表支持每一个修订版本或功能。

El Torito 与混合视图 #

El Torito 向 CD-ROM 卷添加固件可发现的启动记录和启动目录。目录项标识软盘仿真、硬盘仿真或无仿真启动映像。因此，可启动性取决于记录、目录值、映像字节和放置位置，而不只是挂载目录中可见的文件。

混合光盘可以在 ISO 9660、Joliet、Rock Ridge 和 UDF 描述符之间共享文件数据，使不同系统选择不同的目录视图。一些安装程序映像还会将光学启动元数据与用于 USB 启动的 MBR 或 GPT 布局结合起来。重建某一个可见文件系统可能会丢弃其他视图和启动路径。

映像表示 #

映像捕获的是光盘某一选定层：

  • ISO 映像通常存储数据轨道中的 2,048 字节逻辑扇区。它可以包含 ISO 9660、UDF、混合卷或其他块布局；文件扩展名无法标识文件系统。
  • 原始 CD 轨道映像通常存储 2,352 字节扇区。原始扇区保留更多特定于模式的字节，但其自身仍无法描述轨道边界、预间隙、控制标志或会话。
  • BIN/CUE 集将一个或多个二进制轨道文件与一个描述轨道类型、顺序、索引和间隙的提示表配对。保存时两部分都不可缺少。
  • NRG 等容器格式可以存储轨道数据以及供应商特定的布局元数据。哪些元数据能够在转换后保留，取决于工具支持情况。

子通道数据是与 CD 帧关联的另一条数据流。某些复制保护、索引、CD-Text 和时序用例需要特定的子通道，但普通 ISO 或 BIN/CUE 工作流可能会省略它们。仅凭扩展名无法证明完整性；映像文档必须说明扇区模式、子通道处理方式、驱动器行为和读取错误策略。

检查、挂载与提取 #

应在挂载前进行检查，因为挂载会暴露一个文件系统视图，并可能隐藏其他轨道。libcdio 工具可以检查 CD 和 ISO 9660 结构：

sh 
cd-info --no-device-info image.cue
iso-info -i installer.iso
iso-read -i installer.iso -e README.txt -o README.txt
isosize --sectors installer.iso

已安装版本可能不同，因此脚本应核对每个命令的手册，而不是假定选项可用。使用支持相应格式的读取器进行提取，可以将源内容保持为只读，并避免依赖内核挂载。

Linux 可以通过环回设备挂载兼容的逻辑映像：

sh 
sudo mount -o loop,ro installer.iso /mnt/iso

macOS 可以使用以下命令连接可挂载映像：

sh 
hdiutil attach -readonly installer.iso

挂载只能证明某个文件系统解析器接受了某个视图；它不能验证音频、会话、启动路径、原始纠错字节或子通道。

完整性与可复现性 #

可辩护的映像工作流应记录：

  1. 光盘身份、可见状态，以及驱动器型号和固件；
  2. 映像工具、版本、命令、扇区模式和重试策略；
  3. 轨道、会话和子通道元数据；
  4. 每个映像文件及其配套元数据文件的加密哈希；
  5. 读取错误、恢复的扇区，以及重复读取是否一致。

哈希一致性可以保护采集后的文件，但无法证明驱动器返回了每个物理特征。当关注对象是可挂载的软件分发物时，逻辑映像是合适的选择。当轨道语义、音频、会话或仿真器行为很重要时，则需要带有完整布局元数据的原始轨道。
