光学メディアとディスクイメージ

光学メディア、セクタ形式、ファイルシステム、イメージファイルは、それぞれ別の層です。 マウント可能な .iso は、オーディオトラック、セッション境界、サブチャネル、記録特性を省略しながら、データボリュームを再現できます。したがって、イメージ形式は目的に応じて選択する必要があります。目的には、ファイル配布、ブート、エミュレーション、保存があります。

トラック、マーク、読み取り #

CD、DVD、Blu-ray Disc (BD) は、プログラム領域を螺旋状のトラックに沿って保存します。集束レーザーは内側のプログラム領域から外周へその螺旋を追従し、光ピックアップは反射光の変化から信号を生成します。円周は外周に向かって大きくなるため、回転には通常、一定線速度方式またはゾーン方式が使われます。

プレスされた読み取り専用ディスクでは、ポリカーボネートに凹凸パターンを成形し、反射層を追加します。「ピット」と「ランド」は物理的なレベルを表す語であり、文字どおりの 0 と 1 のセルではありません。遷移とラン長によってチャネル信号が生成され、それをドライブが復号して誤り訂正します。CD では Eight-to-Fourteen Modulation と Cross-Interleaved Reed–Solomon Code が使われます。セクタレベルのバイトは、これらの下位層が復号された後に初めて現れます。

物理寸法はファミリーごとに異なります。標準 CD は厚さ 1.2 mm のポリカーボネートディスクで、近赤外レーザーによって読み取られ、トラックピッチは 1.6 µm です。DVD は、より短波長の赤色レーザー、小さなマークとピッチ、さらにオプションの第 2 層によって密度を高めています。BD は青紫色レーザーを使用し、トラックピッチは約 0.32 µm です。螺旋という共通概念があっても、光学系、チャネルコード、セクタ形式が互換になるわけではありません。

プレスメディア、記録可能メディア、書き換え可能メディア #

製造方法と記録方法によって、マークの形成方法が決まります。

  1. プレスされた読み取り専用メディアでは、マスタリング済みの凹凸を成形基板に複製します。電鋳によって現像済みガラスマスターを金属スタンパに変換し、成形、金属化、接着、ラッカー塗布、ラベリングを経て完成ディスクを作ります。
  2. 記録可能メディアは一度だけ書き込めます。CD-R と従来の記録可能 DVD 形式では有機色素を変化させ、一般的な BD-R 設計では無機記録層を使います。書き込まれたコントラストは、互換ドライブが想定する読み取り動作を模倣します。
  3. 書き換え可能メディアでは、通常は相変化合金である可逆記録層を使います。加熱によって、反射率の異なる状態へ領域を切り替えます。

記録可能ディスクには、レコーダーを誘導し、形式固有のアドレス情報やタイミング情報を運ぶ、あらかじめ形成されたグルーブがあります。書き換え可能であっても、ディスクのようなアトミック更新が可能になるわけではありません。パケットライトソフトウェア、欠陥管理、ファイルシステム規則、メディアのファイナライズによって、変更には依然として制約があります。素材の色だけでは配合を特定できず、保存寿命も予測できません。

トラックとセッション #

CD トラックは、CD Digital Audio (CD-DA) や CD-ROM データモードなど、種別が宣言された 1 つの連続ストリームです。1 枚のディスクには複数のトラックを含められます。Mixed-mode と CD Extra のレイアウトは、特定の順序規則のもとでオーディオとデータを組み合わせます。トラック制御フラグは、プレーヤーに解釈方法を伝えます。

セッションは、1 回の記録操作で書き込まれた 1 つ以上のトラックをまとめ、リードインとリードアウトの構造を追加します。マルチセッションリーダーは、セッションメタデータを使ってトラックの位置を特定し、ファイルシステムビューを選択します。セッションを追加すると、以前のセッションのデータを参照する新しいディレクトリツリーを公開できますが、すでに記録されたセクタを書き換えることはありません。ファイルだけをコピーすると、これらの関係は失われます。

仕様ファミリーとセクタ #

色名で呼ばれる Rainbow Books は、CD ファミリーの形式を定義します。

  • Red Book は CD-DA を規定します。
  • Yellow Book は CD-ROM モードを規定します。
  • Orange Book は記録可能 CD と書き換え可能 CD を扱います。
  • Green Book、White Book、Blue Book は、それぞれ CD-i、Video CD、Enhanced CD のアプリケーションを定義します。

ECMA-130 と ISO/IEC 10149 は CD-ROM の記録とセクタ構成を標準化し、IEC 60908 は CD-DA を扱います。ISO 9660 は、CD-ROM セクタ上に別個のボリューム構造とファイル構造を定義します。DVD Forum の仕様と Blu-ray Disc Association の仕様書は、それぞれのメディアを定義します。DVD と BD は Rainbow Book の形式ではありません。

従来の復号済み CD セクタは 2,352 バイトです。CD-DA は 2,352 バイトすべてをオーディオサンプルに使用します。CD-ROM Mode 1 セクタは 2,048 バイトのユーザーデータを公開し、残りを同期、アドレス指定、誤り検出、追加の誤り訂正に使います。Mode 2 の形式では、バイトを異なる方法で分割します。したがって、「セクタサイズ」と言う場合は、チャネルデータ、未加工の復号済みセクタ、ファイルシステムから見えるユーザーデータのどれを意味するかを明示する必要があります。

ファイルシステム層とブート層 #

光学ファイルシステムはユーザーデータセクタを使用しますが、光学マークやすべてのトラックメタデータを定義するものではありません。

ISO 9660 と拡張 #

High Sierra 形式から派生した ISO 9660 は、移植可能な読み取り専用ボリュームとディレクトリ構造を定義します。基本の交換レベルでは、名前とディレクトリ構成に制限があります。Rock Ridge は、System Use フィールドに POSIX 向けの名前、リンク、権限、デバイス情報を記録します。Joliet は、Microsoft が定義した Unicode ディレクトリツリーを追加します。読み取り側は、選択した拡張を明示的にサポートする必要があります。

UDF #

Optical Storage Technology Association の Universal Disk Format (UDF) は、ECMA-167 で定義されたボリューム構造とファイル構造を特殊化したものです。UDF は、DVD、BD、パケットライト、一度だけの記録に必要なメディアモデルと更新モデルをサポートします。リーダーが UDF をサポートしていても、すべてのリビジョンや機能をサポートしているとは限らないため、リビジョンとメディアプロファイルの互換性が重要です。

El Torito とハイブリッドビュー #

El Torito は、CD-ROM ボリュームにファームウェアが検出可能なブートレコードとブートカタログを追加します。カタログエントリは、フロッピーエミュレーション、ハードディスクエミュレーション、またはエミュレーションなしのブートイメージを識別します。したがって、ブート可能性は、マウントしたディレクトリで見えるファイルだけでなく、レコード、カタログ値、イメージバイト、配置にも依存します。

ハイブリッドディスクでは、ISO 9660、Joliet、Rock Ridge、UDF のディスクリプタ間でファイルデータを共有できるため、システムごとに異なるディレクトリビューを選択できます。一部のインストーラーイメージは、光学メディアのブートメタデータと、USB ブート用の MBR または GPT レイアウトも組み合わせます。表示されるファイルシステムを 1 つ再構築すると、別のビューやブートパスが失われる可能性があります。

イメージ表現 #

イメージは、ディスクの選択した層を取得したものです。

  • ISO イメージは、慣例的にデータトラックの 2,048 バイト論理セクタを保存します。ISO 9660、UDF、ハイブリッドボリューム、その他のブロックレイアウトを含められます。ファイル拡張子からファイルシステムを特定することはできません。
  • 未加工 CD トラックイメージは、一般に 2,352 バイトのセクタを保存します。未加工セクタはモード固有のより多くのバイトを保持しますが、それだけではトラック境界、プリギャップ、制御フラグ、セッションを記述しません。
  • BIN/CUE セットは、1 つ以上のバイナリトラックファイルと、トラック種別、順序、インデックス、ギャップを記述するキューシートを組み合わせます。保存には両方が必要です。
  • NRG などのコンテナ形式は、トラックデータとベンダー固有のレイアウトメタデータを保存できます。どのメタデータが変換後も残るかは、ツールのサポートによって決まります。

サブチャネルデータは、CD フレームに関連付けられた別のストリームです。コピー防止、インデックス、CD-Text、タイミングに関する一部の用途では、特定のサブチャネルが必要になりますが、通常の ISO または BIN/CUE ワークフローでは省略される場合があります。拡張子だけで完全性を証明することはできません。イメージ作成の文書には、セクタモード、サブチャネルの扱い、ドライブの動作、読み取りエラーのポリシーを記載する必要があります。

検査、マウント、抽出 #

マウントすると 1 つのファイルシステムビューが公開され、他のトラックが隠れる可能性があるため、マウントに先立って検査を行う必要があります。libcdio のツールは CD と ISO 9660 の構造を検査します。

sh 
cd-info --no-device-info image.cue
iso-info -i installer.iso
iso-read -i installer.iso -e README.txt -o README.txt
isosize --sectors installer.iso

インストールされているバージョンによって動作が異なるため、スクリプトではオプションを仮定せず、各コマンドのマニュアルを確認する必要があります。形式に対応したリーダーで抽出すれば、ソースを読み取り専用として保持でき、カーネルによるマウント要件も避けられます。

Linux では、ループデバイスを通じて互換性のある論理イメージをマウントできます。

sh 
sudo mount -o loop,ro installer.iso /mnt/iso

macOS では、次のコマンドでマウント可能なイメージを接続できます。

sh 
hdiutil attach -readonly installer.iso

マウントによって証明されるのは、1 つのファイルシステムパーサーが 1 つのビューを受け入れたことだけです。オーディオ、セッション、ブートパス、未加工の誤り訂正バイト、サブチャネルが検証されたことにはなりません。

完全性と再現性 #

説明可能なイメージ作成ワークフローでは、次の情報を記録します。

  1. ディスクの識別情報、目視可能な状態、ドライブのモデルとファームウェア。
  2. イメージ作成ツール、バージョン、コマンド、セクタモード、再試行ポリシー。
  3. トラック、セッション、サブチャネルのメタデータ。
  4. すべてのイメージと付随メタデータファイルの暗号学的ハッシュ。
  5. 読み取りエラー、復元されたセクタ、繰り返し読み取りの結果が一致したかどうか。

ハッシュの一致は取得後のファイルを保護しますが、ドライブがすべての物理的特徴を返したことを証明するものではありません。対象がマウント可能なソフトウェア配布物である場合、論理イメージが適しています。トラックの意味、オーディオ、セッション、エミュレーターの動作が重要な場合は、完全なレイアウトメタデータを備えた未加工トラックが必要です。
