Android オープンソースプロジェクトのチェックアウトとビルド成果物には、かなりの ディスク容量が必要です。正確な要件は、ブランチ、ターゲット、有効にするバリアントに よって異なります。十分な RAM、高速なストレージ、チェックアウトと出力ディレクトリの 両方に必要な空き容量を備えた 64 ビット Linux ホストを使用してください。

ソースの取得 #

AOSP は多数の Git リポジトリに分散しています。repo ツールはマニフェストからそれらの リポジトリを調整します。これは Git の Python ラッパーであり、独自のソース管理システム ではありません。repo init で必要なブランチを初期化し、repo sync でチェックアウトを 展開または更新します。

Android のビルドシステムは Soong です。モジュール定義は一般に Android.bp Blueprint ファイルで記述します。Soong は実行に Ninja を使用し、Kati は残りの Android Make 互換 レイヤーをサポートします。AOSP の環境設定スクリプトで製品とビルドバリアントを選択して から、そのブランチで文書化されているビルドターゲットを実行してください。

イメージの実行 #

エミュレーターまたは QEMU は、ターゲットがサポートするイメージとマシン構成でのみ使用 してください。Android 製品はハードウェア固有です。ブートファームウェア、カーネル、 パーティション、デバイス構成が一致している必要があります。汎用的な x86_64 開発では Android Emulator がサポートされる選択肢であることが多く、QEMU は互換性のあるカーネル、 ファームウェア、ディスクレイアウトを試す場合に役立ちます。
